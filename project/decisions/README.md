# Durable Decisions

Create an ADR when a choice is likely to be questioned after its original task closes—for example, a rig-identity rule, telemetry requirement, asset-export constraint, architectural boundary, or quality-tier policy.

Use the filename `ADR-###-short-title.md`. Keep each record short and dated.

```md
# ADR-### — Decision title

**Status:** accepted | superseded
**Date:** YYYY-MM-DD
**Decision:** one sentence

## Context

What constraint or trade-off required a decision?

## Decision

What is now the project rule?

## Consequences

What becomes easier, harder, required, or prohibited?

## References

Links to source, plan, evidence, or replacement ADR.
```

Do not create an ADR for a temporary implementation tactic, untriaged idea, or one-off session note. Those belong in `work/inbox/` or the applicable accepted plan.
