4. progression.ts: closed-form state and shader patch.
   - type ProgressionState = { mode: 'none'|'shaping'|'hobbing'; spaceDepth: Float32Array(10) in [0,1]; engagedSpace: number (-1 none); edgeY: number (mm, cutter leading face during the current stroke; behind it the engaged space has its new depth, ahead the previous depth); hobYc: number (mm); hobA: number (mm centre distance); hobR: number }.
   - progressedRadius(r, y, azimuth, state, shaft: 'legacy'|'approved'): CPU mirror. For legacy shaping, only vertices with FACE_START<=y<=9.875 and r < OD are affected: r' = min(OD, r + (1 - depth_i)*(OD - ROOT)) where i is the tooth-space index from azimuth (clock: measure from the mesh; expose SPACE_CLOCK_RAD constant and a test that recovers it from approved/legacy vertex data you can load in tests via the GLB? if loading the GLB in vitest is impractical, derive the clock from profile-study.json legacy 6.0 polar data instead). For approved hobbing: affected band FACE_START<=y<=13.78: floor(y) = root for y <= hobYc; A - sqrt(R^2 - (y - hobYc)^2) for hobYc < y < hobYc + R; OD beyond; r' = max(r, min(OD, floor(y))). Use the authored untilted circle R=6.0 with centre root+6.0 at final yc 9.5249 for the visual floor so the final state equals the approved mesh; state that R 5.87 tilted is the certified tool and R 6.0 untilted is its equivalent meridian floor (clearance-v4 ramp fit).
