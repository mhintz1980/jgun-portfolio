# JG-034 — Opening-scene refit bug: drawing sheet wrong/missing until first viewport resize

Owner report 2026-09-22 (screenshots taken 2026-09-20 23:44–23:45 on the dev server :5173,
Chrome ≈1919×1030). Owner priority: **must get fixed**.

## Symptom (owner)

The CH.01 ASSEMBLY opening always opens to an incorrect/partial drawing layout (sheet
cropped top-right, PTG-HP-1000 views cut off). It stays wrong through the intro (verified at
SCROLL 004% and 009%). Pressing F12 (opening devtools — i.e. any viewport resize) corrects
the framing immediately; from then on it stays correct.

## Reproduction — 2026-09-22, current working tree at :4173 (fresh build + fresh preview server)

- Fresh load at 1920×1030: canvas renders the procedural backdrop and HUD only — **no
  drawing sheet at all** (`repro1-1920x1030-fresh-load-no-sheet.png`).
- A 1-px viewport resize (1919×1029), no reload: sheet appears, correctly fitted per the
  `src/scene/drawing/sheetCamera.ts` desktop spec (sheet fills 92% h / ~67% w on 16:9,
  border and title block never cropped) (`repro2-after-1px-resize-sheet-correct.png`).
  Matches the owner's F12 recovery exactly.
- Contrast: the same build at 1280×720 rendered correctly on first launch
  (`contrast-1280x720-first-launch-looked-correct.png`) — the bug is viewport- and/or
  timing-dependent, not universal.

## Second, deeper intermittent mode

On a subsequent reload at 1920×1030 the R3F root never initialized at all: the canvas
element stayed at the default 300×150 (client and buffer), `window.__threeCamera` (set
synchronously in `SceneCanvas.tsx` `onCreated`) and `window.__drawingPrint` were never set,
and it was still bricked after a resize. This mode did NOT recover on resize — recorded so
the fix session does not assume a single root cause. Frequency unknown; needs console
capture (the repo's `verify-*.mjs` Playwright harness is the right tool).

## Mechanism hypothesis (to confirm with telemetry, not vision)

`src/scene/drawing/DrawingLinework.tsx:179` builds the sheet layout per R3F size change:
`makeDrawingLayout(size.width / size.height, data.bounds)`. A transient/stale initial
viewport (boot overlay, pre-layout mount, scrollbar appearing after load) yields a wrong
`fitDistance`/`narrow` that nothing re-fits until a real resize event reaches R3F. The
300×150 brick mode suggests the same race can also prevent initialization outright.

Fix direction (not yet an accepted plan): make the initial fit robust to the transient
(measure after the first frames / observe the container), and treat "R3F mounted but never
sized" as a hard, visible error. Verify with before/after telemetry:
`__drawingPrint.layout` (fitDistance, narrow), canvas client+buffer size,
`__threeCamera.aspect`, plus console capture at 1920×1030.
