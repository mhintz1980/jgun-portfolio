- Not shared with the main world: quality ladder. QM has its own `?quality=poster|lite`, a `SceneBoundary` error catch, and its own `webglcontextlost` -> poster (`:23,29,54-56`); it never reads `qualityStore` (tier ladder, PerformanceMonitor DPR steps). - Coupling to watch: `window.__quietMachine` is created by the Preview (`:44-47`) and mutated/read by `QuietMachineScene.tsx:124`, `AirRibbons.tsx:576`, `SectionCaps.tsx:40`; the `webglcontextlost` hook finds the canvas by `document.querySelector('.qm-stage canvas')` (`:55`). - Could it mount at a route today with no change? Yes for rendering: `App.tsx:30-32` already mounts it with the main-page DOM/canvas absent (early return before any main component). What breaks on a path route or a client-side switch: (a) path routes 404 on the host (sec 5); (b) SPA entry from JGUN keeps `scrollY` large, and `:41` then seeks QM to that fraction on mount (needs `scrollTo(0)` first); (c) `App.tsx:30` gates on `!reducedMotion`, so a reduced-motion visitor on the QM route silently gets the JGUN poster page (QM itself supports reduced motion, `:21,25,74`); (d) back-link `<a href="/">` (`:64`) is a full navigation; (e) the 3 verifiers hit `/?study=rl300` literally (`verify-jg033-preview.mjs:66,163,180`).

## 5. Routing

- Hosting: Cloudflare Pages direct upload (`README.md:37`, `project/context/deployment.md:68`). `public/404.html` exists, so unmatched paths return a real 404, NOT an SPA fallback (deployment.md says so; `vite preview` differs and hides it). `_headers` present; no `_redirects`, vercel/netlify config, or CNAME. `vite.config.ts` and `index.html` are single-entry, no `appType`/multi-page config.
- Options: (1) hash route (`/#/quiet-machine`): zero host change, but query params must stay in `location.search`; (2) path route + `public/_redirects` rule `/quiet-machine /index.html 200` (verify on the deployed host); (3) second HTML entry (`rl300/index.html`) via Vite multi-page: hard navigation, fully separate bundles, simplest isolation.
- Enumeration is hard-coded, not data-driven: `SPATIAL_STATIONS` (3 entries, `scrollStore.ts:35-39`) feeds `TechnicalHUD.tsx:213` and `StationNav.tsx:40`; HUD keys 1/2/3 (`TechnicalHUD.tsx:108-113`); `stationForChapter` (`StationNav.tsx:8-12`, same rule in HUD). ## 6. Transition ("fade through dark")
- Existing blackout is NOT a route fade: it is the scroll-scrubbed lamp-flicker/dark pause inside the intro (`introTimeline.ts:197,239-250,357`; `docs/jgun-blackout-emergence-plan.md`; `PostProcessingComposer.tsx:169-171`). No DOM fade overlay or page-transition component exists (BootSequence is a stream-in readout).
- Unmount path: App unmounts `<SceneCanvas/>` only when `canvasActive` flips. R3F v9 unmount disposes after `setTimeout(500)`: `renderLists.dispose(); forceContextLoss(); dispose(scene)` (`node_modules/@react-three/fiber/dist/events-b1bdeb1a.cjs.dev.js:16004-16016`). There is no repo-side dispose/`forceContextLoss` for SceneCanvas.
- Risk, likely but UNVERIFIED at runtime: `SceneCanvas.tsx:424-429` registers a `webglcontextlost` listener (never removed) that calls `forcePoster()` and `exitInspection()`. `forceContextLoss` fires that event, so a normal unmount would flip the global one-way quality ratchet to `poster` (`qualityStore.ts:86-90`) and break a later return to JGUN in the same SPA session. Why it has not shown up: today SceneCanvas unmounts only when the tier already dropped to poster (`App.tsx:40`), where `forcePoster()` returns early (`qualityStore.ts:87`); a route swap would be the first non-poster unmount. A teardown flag guard is needed. A hard navigation avoids it entirely.
- Two live contexts: during the 500ms window the JGUN context (Draco GLBs, drawing sheet textures) coexists with a newly created QM context (about 1.2M tris at full tier per evidence 26, as cited in 29). Browsers cap contexts, but 2 is safe; the real risk is GPU memory on mobile. Mitigation: fade to black, unmount, wait over 600ms, then mount QM, or use hard navigation (new document, old context freed by the browser).
- Reduced motion / poster: `App.tsx:30` blocks the study for reduced motion; JGUN runs the `StaticPoster` + native-scroll path with no canvas and no `ScrollRig` (`App.tsx:40-59,72`), so `StationNav`'s `navigateToStation` uses plain `scrollTo`. A route split needs a decided poster-route behaviour (QM already has 3 poster PNGs and a reduced-motion manual mode; unused due to the `App.tsx` gate).

## Verdict on hypothesis
CONFIRMED with a qualifier. `shot.ts`/`flow.ts`/`QuietMachineScene.tsx` are pure functions of `u in [0,1]`, import nothing from stages or global stores (sec 2), and the only scroll coupling is `QuietMachinePreview.tsx:41,49` over its own 320vh document. The qualifier: `u` is not section-local to a bigger page; it is normalized-global over whichever document it lives in, so it works as its own route and would not work embedded in the main page. Main-page consumers ARE normalized-global (census 02: 71 rows; re-spot-checked 9 `scrollHeight` sites in `src`, sec 3), so the risk sits on the JGUN side.
