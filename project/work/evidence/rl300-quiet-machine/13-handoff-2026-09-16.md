### How to verify a lane, since reports cannot be trusted

Do not read the narrative and believe it. Check:

- **File mtimes against the dispatch time** — this is what caught the zero-byte runs.
- **Grep the target files for marker strings from the spec** (a distinctive constant, a hex
  colour, an API name). Absent markers mean nothing landed, whatever the report says.
- **Re-run every verification command yourself.**
- **`git log --format=%ci`** before believing any claim about commits.

### Standing rules that must appear in every lane spec

1. **Never kill a process.** No `taskkill`, `kill`, `pkill`, `Stop-Process`, for any reason.
   Report a misbehaving process and stop.
2. **Run `codex exec` synchronously in the foreground.** Never background or detach it. If
   it nears a timeout, let it time out and inspect the on-disk diff.
3. **Name the interpreter/runner by absolute path.** A lane that picks its own Python
   reported a broken baseline as the project's real one.
4. **Forbid `TODO.md` / `AGENTS.md` explicitly** — `AGENTS.md:8` orders every agent to read
   the 31 KB `TODO.md`. Carry this ban into any spec a lane writes for a sub-lane.
5. Treat `timeout`'s exit code as unreliable on this machine.
