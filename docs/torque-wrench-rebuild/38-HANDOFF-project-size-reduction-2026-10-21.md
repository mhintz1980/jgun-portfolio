## Procedure

1. Start clean: `git status`, confirm HEAD and that `origin/torque-wrench/rebuild` is still behind.
2. Build a candidate inventory before touching anything. Write it to a manifest, for example `project/work/evidence/CLEANUP-CANDIDATES-2026-10-2X.md`, with path, size, last commit date and reference check per item.
   - Last touch: `git log -1 --format=%cs -- <path>`
   - Reference check: `rg -n "<basename or dir>" TODO.md project docs src scripts public`
   - Anything referenced by `TODO.md`, `project/work/plans`, `project/context`, a handoff in `docs/`, or a `README` stays unless the owner says otherwise.
3. Classify and order by savings:
   - Safe to clear without review, reproducible: `dist`, `node_modules` (reinstall with `npm ci`), `output` (Playwright captures), `.scratch-*` and `.playwright-*` caches.
   - Review with owner: `.scratch` (may hold probes not committed anywhere), `output`, and `project/work/evidence` directories whose only remaining value is the owner conversation.
   - Keep: `src`, `scripts`, `public/models` (role-map and the four allowed GLBs), `project/work/plans`, `project/context`, `project/work/inbox`, `docs/torque-wrench-rebuild` handoffs, `package.json`/`package-lock.json`, `TODO.md`, `GATES.md`.
4. Decide per candidate: delete, move out of the repo, or keep. For anything that cannot be regenerated by a committed script, move it to an out-of-repo archive (for example `C:/Projects/archive/jgun-torque-wrench/2026-10/`) instead of deleting it. Deletion is only appropriate for output that a committed script reproduces.
5. For tracked files, use `git rm -r -- <path>` so the removal is recorded. For untracked or ignored files, delete on disk directly.
6. Verify after each batch: `npm run build`, `npx tsc --noEmit`, `npx vitest run`, then `git status`. If a removal breaks a build, restore that batch from the archive or `git checkout --` for tracked files.
7. Commit in batches with a size summary, then record the result here or in a successor doc. No push without the owner.
