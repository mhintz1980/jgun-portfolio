## 6. Procedural 3D, camera, rendering, and safeguards — source research

- [seen] **Scene/geometry:** the dynamic three.js module creates an opaque-lit procedural keypad assembly, not a loaded model. Rounded bodies and keycaps use ExtrudeGeometry of rounded Shapes (bevelSegments 5, curveSegments 10); the shell is 5.2×3.5 with depth .42 and bevel .08. There are 2×6 keys, cylinders for the rotary dial, a red pointer box, red indicator sphere, a display plane and a large shadow-catching ground plane. A @160450–164500. A's complete initializer is @158850–167950; the only external import there is three.js. Shader plane in the earlier inventory is the full-screen post pass, not the modeled object.
- [seen] **Camera path:** PerspectiveCamera initially `(26°,aspect1,near.1,far100)`; resize supplies actual poses. Desktop (container width≥900) FOV22°, camera `(0,9.6,13)`, lookAt `(.9,-.55,0)`, parent scene offset `(3.2,0,-1.6)`, uniform scale `.74*.81`. Narrow layout FOV30°, camera `(0,10,12.5)`, lookAt `(0,-3.4,0)`, parent offset `(0,0,0)`, scale `.64*.81`. This camera has no authored per-scroll spline/orbit: scroll animates the model's spin/lift and canvas wrapper instead. A @159300–159650, @164750–165400, @173000–173650.
- [seen] **Model path and pointer:** local model rotation is Euler `(-.08+.03*py+.35*spin, -.42+.06*px+.9*spin, .02)`; local Y is `.06*sin(.8*t)+lift`. Hero scroll sets spin `.9*p` and lift `-1.2*p` for progress p. This adds .315 radians X and .81 radians Y over the hero; these two products are [inferred] arithmetic consequences, not additional authored keyframes. Pointer raycasts only key meshes; each distinct hit triggers the .08s/.45s key tween in section 5. There is no frame-dependent lerp on this pointer tilt; assignment follows each event. A @165250–167450, @173150–173550.
- [seen] **Lighting:** no environment/HDR asset is used by the initializer. - [seen] **Custom WebGL shader pair:** only the era-mode full-screen dither pass is authored here. The fragment shader samples `src` (the offscreen scene color/alpha texture), uses uniform `px` (actual renderer pixel ratio) to size 2*px pixel cells, forms a repeating 4×4 ordered threshold pattern, computes luminance with weights (.3,.59,.11), alpha-mixes that luminance against .27, then thresholds `1.15*luminance+pattern` at 1.08 to output opaque black or white. It includes three.js tone-mapping/color-space chunks before quantization. A @159450–160450. This is described, not reproduced.

- prefers-reduced-motion honored? partially, by design: 3 `prefers-reduced-motion` CSS media blocks [seen]; Lenis wrapper defaults `respectReducedMotion:!0` and Lenis only instantiates on ≥992px viewports with smooth wheel — under `reduce` emulation the page loads the identical asset set, still mounts the WebGL canvas, content identical [seen A/B runtime]; GSAP/ScrollTrigger behavior under `reduce` not directly observable in this capture — unknown
- Text in DOM or only in canvas? fully in DOM: hero H1 with `aria-label` + server-rendered per-char/per-line spans (`data-split`, `data-lw`, `aria-hidden` dupes), `sr`-only headings, all sections as HTML; canvas carries no text content [seen DOM]
