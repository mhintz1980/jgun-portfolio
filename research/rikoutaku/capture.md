## 4b. Page and route transitions

- What happens on click of `About` (recorded 80–6000 ms sampling + 6 screenshots):
  1. t≈1–13 ms: `Page.frameRequestedNavigation`/`frameStartedLoading` — no out-animation on the origin page; it unloads almost immediately (home canvas gone by t=80 ms) [seen].
  2. t≈198 ms: new document `/about` committed [seen].

  4. t≈2500 ms: cover released (`ri-covered` removed; reveal sequence `is-lift` → className reset after 950 ms per code), about page + its own NEW canvas visible; curtain element stays mounted under `ri-curtained` [seen].
  5. Total click→content ≈ 2.5 s (load-bound; curtain code caps hold at 10 s) [seen].
- Does the 3D scene persist across pages? **No** — new document, new canvas; the about page builds its own scene (~2.5 s). The GLB comes from HTTP cache on repeat loads [seen (new canvas; cache inferred from no repeat 1829 KB transfer during transition)].

## 4c. Hover, press, cursor and input effects

- **Works lens:** actual home selector is `.composition-two .c2n-work-image`, disabled while the menu is open. Fine mouse pointers show a 112px difference-blended SVG cursor, hide the native cursor on the target, scale the image toward 1.065 and translate it opposite the pointer by up to ±14px horizontally / ±10.5px vertically. Image spring: scale stiffness/damping 210/17, x/y 90/15; cursor follower `1-exp(-25*dt)`, dt capped .05s. Reduced motion removes image motion and cursor lag, not necessarily the lens graphic. Tab, blur, pagehide and pointer exit hide it. [seen] I@109536–109716; B@12523–15990; BC@957–1795
- **3D furniture annotation:** home constructs `tn`, raycasts room groups with a 30Hz limit, draws corner brackets, leader, baseline, dot, `IDEA` and numbered `OBSERVE` label. It uses a .3s draw clock, smoothstep sub-windows and opacity convergence rates 24/s in, 28/s out. Hover holds a flowing furniture group; release blends transport back over .18s. Touch and interactive DOM targets are excluded; 16px hold margin. Large meshes above 6,000 triangles use bounding-box intersection after a sphere test. [seen] I@96500–97143; I@97143–107911; F@5379–6213
- **SVG eyes:** both home logo symbols track mouse angle with a .3s GSAP rotation tween; the call omits an authored ease. GSAP core's bundled default is `quad.out` (`power1.out` alias), not an authored design choice. [seen] I@72503–73700; M@30711

## 8. Accessibility and fallbacks

- prefers-reduced-motion honored? **Yes, in code and verified by emulation.** Gates found in bundles: `fx-live` class withheld (`z||nt.classList.add("fx-live")` where `z=matchMedia("(prefers-reduced-motion: reduce)").matches`), mouse parallax disabled (`matchMedia("(pointer: coarse)").matches||matchMedia("(prefers-reduced-motion: reduce)").matches → this.parallax.enabled=!1`), Tyndall effect `reducedMotion` flag, curtain reduce checks. Emulation check: with `prefers-reduced-motion: reduce` set, `<html>` class = `light is-ready` — **no `fx-live`** (normal: `light fx-live is-ready`); canvas still mounts; scrollHeight shrinks 8083→7483 (motion-gated sections render shorter) [seen]. The 3D room still renders under reduced motion (animation, not presence, is what's reduced) [seen canvas+engine present; exact animation deltas unknown].
- Text in DOM or only in canvas? **All text is real DOM text.** H1/H2 headlines, Japanese body copy, nav, motion captions (`01 — SPACE / 02 — IDEA / 03 — BUSINESS`) are in the DOM; per-character split into spans for animation with `aria-hidden` duplicate spans for screen readers; canvas is a fixed background layer only [seen]. The no-WebGL run still had `h1` text present [seen].
- Pinch zoom allowed? **Yes** — `<meta name="viewport" content="width=device-width, initial-scale=1.0">`, no `maximum-scale`/`user-scalable=no` [seen]; and the custom wheel-scroll handler explicitly passes ctrl+wheel through to browser zoom (`if(r.ctrlKey||!t())return`) [seen].
- No-WebGL fallback? **Partial — and effectively broken.** With WebGL disabled by flag, three.js throws, the site logs an explicit graceful message `"3D experience failed to start; continuing with 2D UI. Error: Error creating WebGL context."` [seen], but the page then stayed on the dark preloader at `LOADING 000%` for 10+ s with zero sections rendered (`sections: 0`, `bodyTextLen: 139`, GLB "preloaded but not used" warnings) — content never became interactive (see `data/no-webgl.png`) [seen]. So: the catch exists; the 2D path it promises does not complete the preloader.
